# 本地快速部署（手机壳上架）

一句话：**把仓库复制到新机器 → 改 `config/` 三个文件 → 起一次 Chrome 登录 → 跑 `check` → 跑 `new`。**

---

## 一、依赖（三样）

| 依赖 | 用途 | 备注 |
|---|---|---|
| **Node.js ≥ 18** | 所有上架脚本 | 建议 20/22 |
| **Python + openpyxl** | 生成「SKU 导入表」（补机型/改库存才用） | 只上架新商品不需要 |
| **Chrome** | 通过 CDP 接管已登录的卖家后台 | 必须用**独立** profile 目录 |

> 这台机器上可直接用的路径（供参考）：
> Python：`C:\Users\Administrator\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe`

---

## 二、目录结构（部署后就是这个样子）

```
taobao-case/
├─ config/                    ★ 换店铺/换机器只改这里
│   ├─ shop.json              ① 模板商品ID ② 标题后缀 ③ 价格/库存/批量参数
│   ├─ models.json            ③ SKU 规格：机型 × 颜色（现在是 130 × 3）
│   └─ image-spec.json        ④ 图片命名规格（主图/3:4/SKU/详情）
├─ bin/
│   ├─ check.js               自检（不碰线上）
│   ├─ new.js                 一条命令上架
│   └─ record.js              回收 ID + 重建清单 +（可选）写台账/推送
├─ 商品图片/<设计名>/           ← 日常只往这里放素材
├─ 商品-手机壳-XXX/item.json    ← 由 config 自动生成，不用手工维护
├─ taobao-phonecase-listing/   能力代码（CDP 接管、填表、上传、提交）
├─ _listing-work/              运行时产物（截图/上传清单/报告），可整目录删
├─ 上架台账.md                  唯一事实来源
└─ 上架ID-逐行.txt / 逗号分隔.txt 由台账派生
```

## 三、`config/` 三个文件要填什么

### 1）`config/shop.json`

| 字段 | 含义 | 现在的值 |
|---|---|---|
| `copyFromItemId` | **① 模板商品ID**：所有新链接都靠它的「发布相似宝贝」复制生成 | `1083698755183` |
| `titleSuffix` | **② 标题后缀**：标题＝素材目录名 + 这个后缀 | `适用苹果18pro手机壳……iPhone套`（权重 80） |
| `catId` | 类目 ID | `150704` |
| `price` / `priceOverrides` | 价格与例外（iPhone 的磁吸款 22.8） | 19.8 / 22.8 |
| `stock` | 每个 SKU 默认库存 | 200 |
| `attributes` / `logistics` | 类目属性、发货与上架方式 | 见文件 |
| `batch` | 单轮条数、上传批量、失败重跑次数 | 6 / 6 / 1 |

**标题的硬规则**：平台上限 100 字符、**汉字按 2 个字符计**；后缀固定占 80，
所以素材目录名最多 20 权重 → 实操是**目录名里的汉字 ≤ 7 个**（`bin/check.js` 会算）。

### 2）`config/models.json` —— ③ SKU 数量与命名

```jsonc
"axes": {
  "颜色分类":   [ { "name": "软壳全包（亮面）", "code": "GLOSS", "group": "款式" }, … ],   // 3 个
  "适用手机型号": [ { "name": "iPhone 18 Pro", "code": "IP-18P", "group": "苹果" }, … ]     // 130 个
}
```

- **数量**＝机型数 × 颜色数（现在 130 × 3 ＝ 390 行 SKU）；
- **命名**：颜色名必须和页面上**完全一致**（多一个"磨砂"两个字都算另一个颜色）；
- 改机型就改这一个文件；根目录的 `机型清单.json` 是历史兼容副本，
  脚本优先读 `config/models.json`，两者不一致时 `bin/check.js` 会提醒（`--fix` 可同步）。

### 3）`config/image-spec.json` —— ④ 图片命名规格

| 类别 | 命名 | 数量 |
|---|---|---|
| 1:1 主图 | `主图_1.jpg … 主图_5.jpg` | 5 |
| 3:4 主图 | `主图3比4_01.jpg … 主图3比4_05.jpg` | 5 |
| SKU 色图 | `SKU_1_全包精孔软壳.jpg`、`SKU_2_磨砂大孔二合一.jpg`、`SKU_3_磁吸磨砂二合一.jpg` | 3 |
| 详情图 | `详情图_1.jpg … 详情图_8.jpg` | 8 |
| 不要的图 | 文件名以 `删除` 开头（如 `删除.jpg`） | 任意，自动跳过 |

合计 **21 张可用图**（目录里通常 23 个文件）。SKU 第 1 张同时当**白底图**用。

## 四、首次部署：6 步跑通第一条

```powershell
# 0) 依赖自检
node bin\check.js

# 1) 起 Chrome（独立 profile；第一次手动登录淘宝，登录态会持久保存）
Start-Process "C:\Program Files\Google\Chrome\Application\chrome.exe" `
  -ArgumentList '--remote-debugging-port=9222','--user-data-dir=C:\Users\Administrator\taobao-automation-profile'

# 2) 确认登录态（脚本会打印"判定: ✅ 已登录"）
node _listing-work\check-login.js

# 3) 放素材：把设计目录丢进 商品图片\<设计名>\（21 张可用图 + 可选"删除"图）

# 4) 自检：配置、素材命名/数量、标题长度、机型规格、待上架清单
node bin\check.js

# 5) 先上 1 条，人工在编辑页核对主图/标题/SKU/详情
node bin\new.js 1

# 6) 没问题就批量（一轮最多 6 条，限流下的安全批量）
node bin\new.js 6
```

记账（上完一批后）：

```powershell
node bin\record.js --since 630 --write        # 回收 ID、写台账、重建 ID 清单
node bin\record.js --since 630 --write --push # 顺带 git 提交推送
```

## 五、必须知道的坑（都花过时间，建议照抄防呆）

1. **1:1 主图必须手选**：页面「从 3:4 主图裁剪生成 1:1」会调 `imageCutUtil/autoCutImages`，
   实测**触发平台滑块验证**，之后整页点不动。脚本已默认走手选。
2. **图片空间根目录会被外部"搜推图"刷屏**：上传脚本按文件名搜索过滤，
   若打印"按名称过滤: 失败"→ 停下来人工看，别硬跑。
3. **上传接口会限流**：整批 21 张在紧额度下必被拒 → 必须 `--chunk 6` 小批投递、跨轮累积；
   被拒就停，不要反复重试（会把限流拖长）。
4. **发布页只留一张**：上传步骤需要它、发布步骤复用它；重复新开会出现"一个宝贝开两个发布页"。
5. **提交报告有落盘延迟**：核对要重试等待，否则会误报"发布未成功"。
6. **偶发失败**：SKU 色图/详情图那几步偶尔走不完 → **清场整条重跑**，
   绝不在图没贴齐的情况下提交（护栏会拦住）。
7. **磁盘至少留 2GB**：写满会伪装成各种怪错（例如"找不到上传输入框"）。
8. **不入库的东西**：素材目录、`_listing-work/`、Chrome profile、`_backups/`（`.gitignore` 已挡住）。
9. **台账是唯一事实来源**：ID 清单、导出文件都由它派生，避免数字打架。

## 六、SKU 的批量修改（补机型 / 改库存）—— 现状说明

平台有两个入口，**能力不一样**，别搞混：

| 入口 | 能做什么 | 实测结论 |
|---|---|---|
| 编辑页 → SKU 区 → 批量导入 → **模板上传** → 下载模版 | 改**已有** SKU 的价格/数量/是否上架 | ✅ 能成（改完要再点"提交宝贝信息"才落库）；模板首行写明**"销售属性不可编辑"→ 加不了机型** |
| 编辑页 → SKU 区 → 批量导入 → **AI识别导入** | 声称能"在当前规格后添加"新机型 | ❌ 能识别出缺哪些机型，但点了不落库（接口无成功写入） |

所以「老链接加机型」这件事，**只能靠重新发布**（用已含 130 机型的模板商品复制一条新链接、
换上素材，再删旧的），代价是商品 ID 会变、要重跑主图/详情，单条约 2.5–3 分钟。
