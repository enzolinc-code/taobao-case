# 机型清单：全店共用一份

300 个链接、每个几十个机型，如果每个 `item.json` 都抄一遍机型列表，会有三个后果：

1. 新增一个机型（比如 iPhone 17）要改 300 个文件；
2. 同一个机型在不同文件里写法不一致（`iPhone15Pro` / `iPhone 15 Pro` / `苹果15Pro`），SKU 行匹配不上，批量跑的时候一半链接失败；
3. 下架某个型号时漏改几个文件，链接里留着已经停产的机型。

所以机型列表抽出来一份，`item.json` 只写"我要哪几个"。

## 一、放在哪、怎么引用

把 `assets/model-list.template.json` 复制成 `机型清单.json`，放在**商品文件夹的上一级**，脚本会从商品文件夹往上找（最多 5 层）：

```text
项目根\
├── 机型清单.json
├── 商品-黑猫-001\
│   ├── item.json
│   └── images\
└── 商品-星空-002\
    └── item.json
```

`item.json` 里这样引用：

```json
"axes": {
  "适用机型": { "fromRegistry": "机型清单.json", "axis": "适用机型", "groups": ["苹果"] },
  "颜色": ["黑色磨砂", "透明白"]
}
```

两种写法可以混用：**直接给数组的轴照旧**，只有写成对象的轴才去查机型清单。`item.json` 顶部还可以写 `"registry": "另一个清单.json"` 换掉默认文件名。

## 二、清单里每项能写什么

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | **填进 SKU 轴的值**。全店统一，改一次全店生效 |
| `code` | 否 | 用来拼商家编码（见第四节） |
| `group` | 否 | 分组，方便按品牌筛（`groups: ["苹果"]`） |
| `enabled` | 否 | 写 `false` 表示暂时不上这个型号，全店都不上 |

**命名规则**：`name` 会原样填进 SKU 表。颜色这类下拉轴必须用**平台原词**；机型这类自定义输入轴，保持全店写法统一即可（脚本按行文本匹配，写法不一致就匹配不到）。清单里出现重复的 `name` 会直接报错——重复值会让平台把 SKU 行合并。

## 三、按商品筛选

```json
"适用机型": {
  "fromRegistry": "机型清单.json",
  "groups": ["苹果", "华为"],
  "except": ["iPhone 13"],
  "limit": 40
}
```

| 字段 | 作用 |
|---|---|
| `only` | 只要这些（可以写型号名或 group 名） |
| `groups` | 只要这些分组 |
| `except` | 排除这些（型号名或 group 名） |
| `limit` | 最多取前 N 个（用于控制单链接的 SKU 行数） |
| `axis` | 引用清单里的哪个轴，默认和 item 里的轴名相同 |

筛选顺序：先去掉 `enabled: false`，再 `only` → `groups` → `except` → `limit`。筛完为空会直接拦截，不会生成一个没有 SKU 的商品。

## 四、自动生成商家编码

`item.json` 里写：

```json
"outerId": "PC-0413",
"outerIdPattern": "{prefix}-{适用机型.code}-{颜色.code}"
```

生成的编码形如 `PC-0413-IP15P-BLK`。规则：

- `{prefix}` 取 `item.outerId`；
- `{轴名.code}` 取机型清单里该条目的 `code`，没写 `code` 就留空并提示；
- 显式写了 `outerId` 的那一行不会被覆盖；
- 不写 `outerIdPattern` 就完全不生成（默认行为）。

## 五、开批量之前先干跑

```bash
node <skill>/scripts/resolve-item.js --item 商品\黑猫-001\item.json
node <skill>/scripts/resolve-item.js --scan 商品
```

不连浏览器，只算数据。输出：每个商品最终用多少个轴值、多少 SKU 行、前几行的价格库存编码，以及所有拦截项；`--scan` 还会给出全店合计和问题商品清单（明细写到 `_listing-work/resolve-report.json`）。

这一步能拦掉绝大多数"跑到一半才发现"的错误：清单路径写错、分组名拼错、SKU 行数爆炸、编码模板缺 code。**它是唯一能在开浏览器之前发现问题的环节，别跳过。**

## 六、常见错误

| 报错 | 原因 |
|---|---|
| `找不到机型清单: …` | 路径不对，或者清单不在商品文件夹的上层目录里 |
| `轴「适用机型」引用的 … 里没有「适用机型」` | `axis` 名字和清单里的键名不一致 |
| `轴「适用机型」筛选后没有任何机型` | `only`/`groups` 拼错，或者候选全被 `enabled: false` 关掉了 |
| `机型清单.适用机型 有重复值` | 清单里有同名条目，删掉一个 |
| `「iPhone 13」没有 code，编码里会留空` | 该条目没写 `code`，补上或接受空值 |
