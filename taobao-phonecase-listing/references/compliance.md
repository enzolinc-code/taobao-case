# 合规边界、人机分工与批量预算

## 一、平台明文红线

### 品牌词必须带适用词（手机壳直接相关）

依据淘宝《3C数码配件发布规范》：手机壳、手机膜、充电宝等叶子类目**可以用品牌词，但必须加"适用于"**，
标题、导购标题、图片都要加，字号不小于 50%，否则下架、删除、扣分。
官方原文：https://qn.taobao.com/headline/news/10701499/

脚本能拦的：标题文字。脚本拦不了的：图片里的文字 → 人工看。

### 图片与实物相符

AI 生成的假模特图、换装图不要直接当主图。主图真实性是平台明确要求的。

### 不做的事

- 刷单、虚假交易、评价买卖
- 群控、外挂、抢单插件
- 站外导流、诱导性文案
- 伪造资质、规避类目资质
- **硬闯验证**：滑块、短信、人脸一律交真人

## 二、关于"官方 API"这件事的更正

早先的笔记里写过"淘宝没有面向普通店铺的商品发布 API"。**这个说法不准确**，需要更正：

- 淘宝开放平台**确实有商品发布接口**：`alibaba.item.publish.schema.get`（取发布规则）、
  `alibaba.item.publish.submit`（商品发布），配套还有 SKU、图片、上下架、库存价格接口。
  文档：https://open.taobao.com/doc.htm?docId=119447&docType=1
- 但权限按"权限包"审批，入驻走的是**企业身份**，自研入口是"自研OMS"（归属天猫商家自研发）。
  文档：https://open.taobao.com/doc.htm?docId=120867&docType=1 、
  https://open.taobao.com/doc.htm?docId=121813&docType=1

**结论**：个人店铺走不通这条官方通道，浏览器自动化是个人店铺的现实路径；
这条路径的风险由本文件的第三节和第四节约束。

## 三、人机分工

### 脚本可以做的

- 打开发布页、填标题、属性、SKU 矩阵、价格、库存、上传图片、选物流
- 读回页面错误标记和风控信号、截图存档、写账本

### 必须真人做的

- 扫码登录（登录态过期时）
- **点提交**（除非显式开 `--submit`）
- **首次类目核对**：新类目的属性映射、SKU 轴、图片要求，第一次由人看一遍
- 验证码 / 二次验证 / 人脸
- 资质提交、类目报备、活动报名
- 改价、下架、删除商品

## 四、批量预算与限频

**先承认不确定性**：下面两个数字是保守起点，不是平台公布的限额，也没有经过大规模实测。

| 参数 | 默认值 | 来源与性质 |
|---|---|---|
| 每日上架预算 | 10 个 | 本 skill 的保守默认，可用 `--per-day` 覆盖 |
| 任务间停顿 | 20–60 秒随机 | 本 skill 的保守默认，可用 `--pause-min/--pause-max` 覆盖 |
| 单店单日 2 个 | 女装店的经验值 | 来自同目录的另一套笔记，**在 200–300 条的规模下明显不可行**，本 skill 没有采用 |

为什么保留预算机制：200–300 个链接、每个几十行 SKU，一次跑完等于在几小时内产生上万个表单操作，
这是最容易触发风控的行为模式。建议的做法是：

1. 先 1 个 → 再 5 个 → 再看 20 个，每一步观察有没有验证、限流、错误率抬升；
2. 稳定后逐档提高 `--per-day`，而不是一上来就全量；
3. 出现任何风控提示，**当天停止**，不要换参数重试。

## 五、脚本自己会停的情况

- 页面跳登录 → `login-required`
- 检测到滑块/短信/人脸/操作过于频繁 → `blocked`，整批中止，剩余标记 `not-started`
- 预检拦截（标题违规、SKU 重复、价格库存非法）→ `blocked`，不开页面
- 连续 3 个没跑通 → 停止整批，提示先修 `selectors.json`

这些是设计上的刹车，不要为了"跑得快"去关掉它们。
